# 35 · 工具 · 安卓模拟器（AVD）

> 用 Google 官方 Android 模拟器（AVD）在 Ubuntu 上跑安卓环境，adb 装 APK / logcat 调试，
> 替代雷电/夜神（它们没有 Linux 版）。

---

## 背景

需要在本地调试安卓 app（装 APK、看日志、复现问题）。第一反应是雷电/夜神，但调研结论：

| 模拟器 | Linux 支持 | 结论 |
|--------|-----------|------|
| 雷电 LDPlayer | ❌ 仅 Windows | 魔改 VirtualBox 方案，依赖 Windows 驱动，Wine 硬跑不可行 |
| 夜神 NoxPlayer | ❌ 仅 Windows/macOS | 同上 |
| MuMu | ❌ 仅 Windows/macOS | 同上 |
| **AVD 官方模拟器** | ✅ 原生 | KVM 硬件加速，开发调试正统（adb/logcat/任意 API 级别） |
| Waydroid | ⚠️ 要求 Wayland | 桌面是 X11，需嵌套 Weston，体验打折，未采用 |
| Genymotion | ✅ | 需注册账号 + VirtualBox 内核模块，内核更新易踩坑，未采用 |

## 目标 / 现状

装机前环境侦察（2026-09-23 实测）：

| 检查项 | 结果 |
|--------|------|
| `/dev/kvm` | ✅ 存在（root:kvm 660，AMD 16 线程 SVM） |
| KVM 访问权 | ✅ logind ACL 给活动桌面会话用户直接授权（`getfacl /dev/kvm` 见 `user:$USER:rw-`） |
| 桌面协议 | X11（Waydroid 因此出局） |
| Java | OpenJDK 17.0.20（sdkmanager 依赖，已装） |
| 网络 | dl.google.com 直连 200、实测下载 9.9MB/s（无需镜像） |
| 磁盘 | /home 余 322G（实际装完占 4.7G） |

装机后版本：

| 组件 | 版本 |
|------|------|
| commandline-tools | build 13114758（v13.0，2024-11） |

## 解决方案

### 一键执行（推荐）

```bash
cd <本仓库目录>
bash scripts/install-android-emulator.sh install   # 装全部组件 + 建 AVD + 启动器
bash scripts/install-android-emulator.sh verify    # 启动实测（开机/adb/截图）
```

### 手工步骤（理解原理用）

```bash
# 1. 下载 commandline-tools（~165M，走 dl.google.com 直连）
aria2c -x8 https://dl.google.com/android/repository/commandlinetools-linux-13114758_latest.zip
# sha256: 7ec965280a073311c339e571cd5de778b9975026cfcbe79f2b1cdcb1e15317ee

# 2. 解压到固定位置（必须是 cmdline-tools/latest/ 这个层级，sdkmanager 认路径）
mkdir -p ~/Android/Sdk/cmdline-tools
unzip commandlinetools-linux-13114758_latest.zip -d /tmp/clt
mv /tmp/clt/cmdline-tools ~/Android/Sdk/cmdline-tools/latest

# 3. 接受许可 + 装包（system image ~1.4G 是大头）
export ANDROID_HOME=~/Android/Sdk
yes | $ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager --licenses
$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager \
    "platform-tools" "emulator" "platforms;android-35" \
    "system-images;android-35;google_apis;x86_64"

# 4. 创建 AVD（Pixel 6 外形，Android 15）
echo no | $ANDROID_HOME/cmdline-tools/latest/bin/avdmanager create avd \
    -n dev35 -k "system-images;android-35;google_apis;x86_64" -d pixel_6

# 5. 启动（桌面双击「Android 模拟器」图标同理）
emulator -avd dev35

# 6. 验证
adb devices                     # emulator-5554 device
adb shell getprop sys.boot_completed   # 1（KVM 下开机仅数秒）
```

## 参数 / 配置详解

- **为什么选 android-35 google_apis x86_64**：35（Android 15）兼容面广且镜像成熟；
  google_apis 带谷歌服务框架但无 Play 商店（免谷歌账号登录，比 playstore 镜像少一层依赖）；
  x86_64 是 KVM 直跑架构，性能最佳。
- **ARM 翻译层是隐藏福利**：android-35 google_apis x86_64 镜像自带 ndk_translation
  （`adb shell getprop ro.product.cpu.abilist` → `x86_64,arm64-v8a`），ARM-only 的 APK
  用 `adb install --abi arm64-v8a -r xxx.apk` 也能跑（性能略降）。
- **commandline-tools 版本固定 13114758**：repository XML 分发的最新 build；更新的 build
  只在 developer.android.com/studio 网页挂（本机访问该页龟速），但 sdkmanager 只是个
  "装包器"，emulator/镜像版本走 XML 实时拉，工具链旧一点无影响。
- **KVM 权限双保险**：
  1. logind ACL——对"活动桌面会话"用户自动授权（零配置，但 SSH 无桌面会话时可能失效）；
  2. kvm 组——`sudo usermod -aG kvm $USER`（持久，重登生效）。
  两者任一即可访问 `/dev/kvm`。
- **GPU 直通 `-gpu host`**：AMD RADV 下实测正常（主屏渲染无花屏），无需 swiftshader。
- **命令入口**：`~/bin/` 下 adb / emulator / sdkmanager / avdmanager 四条软链（该目录
  已在 PATH），不污染 shell rc。

## 验证方法

验收标准（2026-09-23 全链路实测通过）：

1. **开机速度**：冷启动到 `sys.boot_completed=1` 约 5 秒（KVM + x86_64）
   （验：`adb shell getprop sys.boot_completed` 返回 `1`）
2. **adb 联通**：`emulator-5554 device`
   （验：`adb devices` 列出 `emulator-5554`，状态 `device`）
3. **图形渲染**：主屏/图标/壁纸全部正常（GPU host 模式，AMD RADV）
   （验：`adb exec-out screencap -p > /tmp/x.png` 截图目检）
4. **装 APK**：实测「包子漫画 v1.0.21」
   - 默认装（x86_64）：闪退 —— APK 的 x86_64 lib 目录缺 360 加固壳 so（19 个 so 只带 9 个）
   - `--abi arm64-v8a` 强制 ARM 翻译层：`Success`，MainActivity 正常到前台
   - 结论：ARM-only APK 有解，加固壳 so 不全是 APK 自身问题，非模拟器故障
   （验：`adb install --abi arm64-v8a -r xxx.apk` 后 `dumpsys activity activities | grep topResumedActivity` 显示目标 Activity）

```bash
adb install -r myapp.apk                  # 装自己的 app（调试主场景）
adb install --abi arm64-v8a -r myapp.apk  # ARM-only APK 走翻译层
adb logcat -s MyAppTag                    # 按标签看日志
adb logcat -d -b crash                    # 只看崩溃日志
adb emu kill                              # 关闭模拟器
```

## 常见问题

**Q1：雷电/夜神真没有 Linux 版？**
没有。三家（雷电/夜神/MuMu）都是 Windows 的 VirtualBox 魔改方案，官方从未出 Linux 版；
Wine 跑不起来（依赖 Windows 内核驱动）。Linux 开发调试就用官方 AVD。

**Q2：APK 装上秒闪退？**
先看崩溃栈：`adb logcat -d -b crash`。
- 若 `UnsatisfiedLinkError` 且 so 名带 `jiagu`/`InnoSecure` 等 → APK 是加固的且 so 不全：
  试 `adb install --abi arm64-v8a -r xxx.apk` 走翻译层；
- 若无崩溃但闪屏后回桌面 → 加固壳的**反模拟器检测**（静默退出），任何模拟器都会中招，
  真机不受影响，无解，属 app 自身行为。
- 自己开发未加固的 app 不会遇到以上两种情况。

**Q3：SSH 远程时模拟器报 /dev/kvm 权限错？**
logind ACL 只对"活动桌面会话"生效。确认在 kvm 组（`id -nG | grep kvm`）；
不在则 `sudo usermod -aG kvm $USER` 后**注销重登**（新进程才有组身份）。

**Q4：怎么再建一个不同安卓版本的模拟器？**
```bash
sdkmanager "system-images;android-34;google_apis;x86_64"
avdmanager create avd -n dev34 -k "system-images;android-34;google_apis;x86_64" -d pixel_6
emulator -avd dev34
```

**Q5：模拟器能上网吗？**
能，默认 NAT 共享宿主网络，Chrome/应用直接可用。

**Q6：内存占用？**
运行时单实例约 2~4G 内存。本机 60G（LLM 推理常驻 ~30G）下与 :1234 服务可共存。

## 影响范围 / 安全权衡

- 全部组件装在用户目录（`~/Android/Sdk` 4.7G + `~/.android/avd`），**无系统级改动**；
  唯一系统变更是加入 kvm 组（`uninstall` 不自动退组，无害）。
- `uninstall` 子命令可完整回滚。
- agent 沙箱内 sudo 被 NO_NEW_PRIVS 拦时，可用项目先例方案加组：
  `docker run --rm -v /:/host alpine chroot /host usermod -aG kvm $USER`（docs/24 先例）。

## 边界声明（不做什么）

- **不装 Android Studio IDE**——本方案只要"独立模拟器 + adb"（等价雷电用法）；
  要写原生安卓代码时另行安装（约 10G）。
- **不做 Waydroid / Genymotion / redroid**——X11 桌面 / 注册账号 / CI 无头场景各有硬伤，见背景对比表。
- **不预装多安卓版本**——只建 dev35 一个 AVD；需要其他版本见 Q4 自行扩展。
- **不处理反模拟器检测的加固 app**——那是 app 自身行为（见 Q2），任何模拟器无解。
