# 30 · 工具 · 微信开发者工具（WeChat DevTools for Linux）

> 一句话：在 Ubuntu 上安装社区移植版微信开发者工具（小程序开发 IDE），用于小程序项目的创建、编辑、调试、预览与上传。

---

## 背景

开发微信小程序需要官方「微信开发者工具」IDE，但腾讯**只发 Windows / macOS 版，官方无 Linux 版**。主流可行方案是社区项目 [msojocs/wechat-web-devtools-linux](https://github.com/msojocs/wechat-web-devtools-linux)：把官方 Windows 包重打包为原生 Linux 应用（Electron/NW.js + 自研 wx-compiler 编译 wxml/wxss，**不依赖 Wine**），持续跟随官方版本更新（本项目实测构建到官方 2026-08-07 的 2.02.2608070）。

## 解决方案

### 一键执行（推荐）

```bash
# 进入仓库目录
cd <本仓库目录>

# 一键下载 + 安装 + 软链 + 校验（需 sudo）
sudo bash scripts/install-wechat-devtools.sh
```

脚本会：

1. 经 `gh-proxy.com` 镜像下载 `io.github.msojocs.wechat-devtools-linux_2.02.2608070-1_amd64.deb`（约 204M）到 `~/Downloads`（直连 github.com 不通，见 Q1）
2. `dpkg -i` 安装（自包含包，2026-09-15 实测无依赖问题）
3. 创建 `wechat-devtools` / `wechat-devtools-cli` → `/usr/local/bin` 软链
4. 校验 `dpkg -l` / 安装路径 / 桌面菜单项 / 软链

### 手工步骤（理解原理用）

```bash
# 1. 下载（走 gh-proxy 镜像；直连 github.com 本机超时）
curl -fL -o ~/Downloads/wechat-devtools.deb \
  "https://gh-proxy.com/https://github.com/msojocs/wechat-web-devtools-linux/releases/download/v2.02.2608070-1/io.github.msojocs.wechat-devtools-linux_2.02.2608070-1_amd64.deb"

# 2. 安装
sudo dpkg -i ~/Downloads/wechat-devtools.deb

# 3. 命令行软链（deb 自带的启动器不在 PATH 里）
sudo ln -sf /opt/apps/io.github.msojocs.wechat-devtools-linux/files/bin/bin/wechat-devtools /usr/local/bin/wechat-devtools
sudo ln -sf /opt/apps/io.github.msojocs.wechat-devtools-linux/files/bin/bin/wechat-devtools-cli /usr/local/bin/wechat-devtools-cli

# 4. 启动：Super 键搜索 "微信开发者工具"，或命令行：
wechat-devtools &
```

首次启动弹出登录窗口，用微信扫码（或左下角「游客模式」）。

## 参数 / 配置详解

### 为什么选社区 deb 而不是 Wine / 自构建

| 方案 | 优点 | 缺点 |
|------|------|------|
| **社区预构建 deb（采用）** | 原生 Electron 不依赖 Wine、apt 可管理、版本紧跟官方（滞后约 1 个月） | 非官方包，见「影响范围」 |
| Wine 跑 Windows 版（cytle/yuan1994 等老项目） | 与官方版本 100% 一致 | Wine 兼容性差、登录失效/白屏问题多、老项目基本停更 |
| Docker 自构建（项目 `tools/build-with-docker.sh`） | 可构建任意版本 | 需拉子模块 + 构建 30 分钟+，日常使用没必要 |

### deb 包内容结构（统信 UOS 规范布局）

```
/opt/apps/io.github.msojocs.wechat-devtools-linux/
├── files/
│   ├── bin/
│   │   ├── bin/wechat-devtools        # GUI 启动器（bash 包装：设环境变量 + 起 electron）
│   │   ├── bin/wechat-devtools-cli    # CLI V2 启动器
│   │   ├── electron/                  # Electron 36.6.0 运行时
│   │   ├── node/                      # 内置 Node 22.16.0
│   │   └── resources/app              # 主程序（官方包解包重打包）
├── entries/                           # desktop 文件 + 图标
└── info
```

GUI 启动器逻辑要点：按 `resources/.build_time` 与 `~/.config/wechat-devtools/app/.build_time` 的 diff 自动清理编译缓存（`WeappCache`/`WeappVendor`）——**升级版本后首次启动会自动重建缓存，属正常现象**。

### CLI V2（自动化 / CI 用）

`wechat-devtools-cli` 对齐官方 CLI V2，常用子命令：

```bash
wechat-devtools-cli open --project /path/to/miniprogram   # 打开项目
wechat-devtools-cli preview --project ...                 # 预览（生成二维码）
wechat-devtools-cli upload --project ... -v 1.0.0 -d "描述"  # 上传代码
wechat-devtools-cli build-npm --project ...               # 构建 npm
wechat-devtools-cli auto --project ... --auto-port 9420   # 开自动化（miniprogram-automator 联调）
```

**前置条件**：先在 GUI 里 **设置 → 安全设置 → 开启服务端口**，否则 CLI 连不上 IDE。


## 常见问题

**Q1：下载直连 github.com 超时？**

本机（2026-09-15 实测）直连 `github.com:443` 不通（`api.github.com` 反而可达）。脚本默认走 `gh-proxy.com` 镜像前缀（实测 500KB/s，204M 约 7 分钟）；备用 `ghfast.top` 也可达。若镜像也失效，可用 v2rayN 代理后再 `curl` 直连。

**Q2：怎么升级到新版？**

到 [Releases 页面](https://github.com/msojocs/wechat-web-devtools-linux/releases) 看最新 tag（命名 `v<版本>-1`），然后：

```bash
sudo WXDT_VERSION=<新版本号>-1 bash scripts/install-wechat-devtools.sh all
```

覆盖安装不清登录态（用户数据在 `~/.config/wechat-devtools/`）。首次启动自动清编译缓存重建，稍慢属正常。

**Q3：CLI 报「无法连接 IDE」/ 端口不通？**

在 GUI 里 **设置 → 安全设置 → 开启服务端口**。开启后 `wechat-devtools-cli islogin` 能正常返回登录态。

**Q4：模拟器里 Skyline 渲染模式不可用？**

Skyline 为实验性功能，上游 README 明确需要额外运行其配套 docker 服务端，日常 WebView 渲染模式开发不受影响。

**Q5：这是非官方包，有什么风险？**

- 包由官方 Windows 版解包重打包而来，安装与运行时会连腾讯服务器（登录/更新/遥测 `galileotelemetry.tencent.com`），扫码登录即腾讯账号体系，与官方版行为一致
- 社区构建（MIT 项目），理论上存在供应链信任问题；如敏感项目介意，可自行用官方 `tools/build-with-docker.sh` 从源码构建
- 腾讯不承诺兼容性，极端情况（如官方强制校验客户端）可能失效，届时关注上游 issue

**Q6：怎么彻底卸载？**

```bash
sudo bash scripts/install-wechat-devtools.sh remove   # 系统包 + 软链 + deb 安装包
rm -rf ~/.config/wechat-devtools                      # 用户数据（登录态/项目列表，彻底清理时用）
```

**Q7：小程序/前端工程能放在 win_d/win_e（NTFS 分区）上吗？——不能！**

2026-09-15 实测踩坑（症状极具迷惑性，排了一下午）：

- **症状**：IDE 打开 NTFS 分区上的 uni-app 工程，点「编译/预览」**完全无反应或永久转圈**——日志停在 `createBuilder enter` 不再推进、进程 CPU 0%、无网络请求、模拟器只显示骨架屏（会被误认为"渲染成功"）
- **根因**：IDE 编译初始化要在工程目录上建文件监听（日志可见 `DevtoolsFileWatcher` 挂在工程路径），**FUSE 的 ntfs-3g 上 inotify 支持不完整，watch 挂死 → 编译链永久 pending**
- **验证方法（对照实验）**：把 `unpackage/dist/dev/mp-weixin` 产物拷到 ext4 建壳项目（同 appid + project.config.json），IDE 导入后立刻能编译——一锤定音
- **解法**：**整个工程仓库迁到 ext4**（本机迁到 `~/项目/demo-business/`，rsync 排除 node_modules/target/logs 后约 1.1G），NTFS 上的旧工程留给 Windows 双系统用，两边以 git 同步
- **连带退役**：node_modules 的 bind mount（fstab 行已删）；`--legacy-peer-deps` 仍需保留（pinia 2.1.7 的 peerOptional 冲突，与文件系统无关）
- **教训**：NTFS 放"文档/下载/备份"可以，放**需要编译、watch、执行脚本的前端工程**不行（执行位坑见 docs/01 Q6，watch 坑见本条，两连坑）

**Q8：点预览报「系统错误 1005」？**

登录 ticket 过期（2 小时有效期），重新扫码登录即愈。间隔几小时没动 IDE 后首次预览容易遇到。

**Q9：HBuilderX 的 uni-app 工程在这个 IDE 里怎么编译？**

工程若来自 HBuilderX（`package.json` 无 scripts、`vite.config.js` 却是 CLI 写法），补 CLI 编译链即可，源码零改动：

```jsonc
// package.json 关键内容（版本与 vue/vite 精确配套，2026-09 实测）
{
  "scripts": {
    "dev:mp-weixin": "UNI_INPUT_DIR=$PWD UNI_OUTPUT_DIR=$PWD/unpackage/dist/dev/mp-weixin uni -p mp-weixin",
    "build:mp-weixin": "UNI_INPUT_DIR=$PWD UNI_OUTPUT_DIR=$PWD/unpackage/dist/build/mp-weixin uni build -p mp-weixin"
  },
  "devDependencies": {
    "@dcloudio/uni-app": "3.0.0-alpha-5020620260914001",
    "@dcloudio/uni-mp-weixin": "3.0.0-alpha-5020620260914001",
    "@dcloudio/vite-plugin-uni": "3.0.0-alpha-5020620260914001",
    "sass": "^1.77.0",
    "vite": "5.2.8"
  },
  "dependencies": { "pinia": "2.1.7", "vue": "^3.4.21" }
}
```

- uni 版本用 dist-tag `vue3` 的最新号（`npm view @dcloudio/vite-plugin-uni dist-tags`），vite 被 uni 精确 pin（5.2.8），pinia 锁 2.1.7（2.3.x 要求 vue≥3.5.11 会冲突）
- `npm install --legacy-peer-deps`（pinia 的 peerOptional @vue/composition-api 与 vue3 冲突，npm 过严）
- IDE 导入**工程根目录**（`project.config.json` 已配 `"miniprogramRoot": "unpackage/dist/dev/mp-weixin/"`）
- 日常：`npm run dev:mp-weixin` 起 watch → 改 `.vue` 自动重编译 → IDE 模拟器自动刷新；正式包 `npm run build:mp-weixin`
- 工程必须在 **ext4**（见 Q7）

## 影响范围 / 安全权衡

- 安装目录 `/opt/apps/io.github.msojocs.wechat-devtools-linux/`（约 900M，含 Electron 与 Node 运行时，自包含）
- deb 自带 desktop 文件并自动注册（含 `MimeType=x-scheme-handler/wechatide`，浏览器 `wechatide://` 链接可唤起 IDE）
- 本项目手工加了 `/usr/local/bin/wechat-devtools{,-cli}` 两个软链（卸载时随 remove 清理）
- 运行时联网：腾讯账号服务器（登录/预览/上传）+ GitHub（更新检查）；上报遥测到腾讯
- 非官方移植版，风险见 Q5
