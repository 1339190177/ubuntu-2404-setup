# 16 · 网络 · 静态 IP 配置

> 把有线网卡 eno1 从 DHCP 动态获取改为静态 IP，确保 frpc、hosts、Docker 服务等
> 依赖固定 IP 的配置不会因路由器重新分配而失效。

---

## 背景

本机作为常驻服务器使用，跑了 Docker 服务（MySQL/Redis/frpc/业务应用），多处配置依赖固定 IP：

- `frp/frpc/frpc.ini` 里 `local_ip = 192.168.1.13`
- `/etc/hosts` 里业务域名解析
- 内网其他设备访问本机服务的地址

DHCP 动态分配的 IP 一旦变化，以上全部失效。因此需要固定为静态 IP。

> **替代方案**：也可以在路由器后台做 DHCP MAC 绑定（不改本机配置，更省心）。
> 本文采用本机静态 IP 方案，不依赖路由器。

## 目标 / 现状

| 项目 | 内容 |
|------|------|
| 网卡 | `eno1`（有线）|
| MAC 地址 | `AA:BB:CC:DD:EE:FF` |
| IP | `192.168.1.13/24`（固定前是 DHCP，固定后静态）|
| 网关 | `192.168.1.1`（路由器）|
| DNS | `192.168.1.1`（路由器）+ `10.0.0.53` + `10.0.0.54`（内网 DNS）|
| 连接名 | `netplan-eno1`（NetworkManager 管理）|
| 连接 UUID | `<连接UUID>` |
| 配置日期 | 2026-08-10 |

## 解决方案

### ⚠️ 操作前必做：备份 + 准备回滚

改网络配置有断网风险，**操作前必须备份**。万一断网，需物理接触机器恢复。

```bash
# 备份 netplan 配置
BACKUP_DIR="<本仓库目录>/backups/network-$(date +%Y%m%d-%H%M%S)"
sudo mkdir -p "$BACKUP_DIR"
sudo cp /etc/netplan/*.yaml "$BACKUP_DIR/"
nmcli connection show netplan-eno1 > "$BACKUP_DIR/nmcli-connection-before.txt"
```

### 设置静态 IP（nmcli，推荐）

本机网络由 NetworkManager 管理，**不要直接改 netplan 的 yaml 文件**（会被 NM 覆盖）。
用 `nmcli` 修改连接配置，NM 会自动同步到 netplan 文件。

```bash
# 1. 修改配置（此时不会立即生效，安全）
sudo nmcli connection modify netplan-eno1 \
  ipv4.method manual \
  ipv4.addresses 192.168.1.13/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "192.168.1.1 10.0.0.53 10.0.0.54"

# 2. 验证配置（确认参数无误后再应用）
nmcli -t -f ipv4.method,ipv4.addresses,ipv4.gateway,ipv4.dns \
  connection show netplan-eno1
# 应输出：
# ipv4.method:manual
# ipv4.addresses:192.168.1.13/24
# ipv4.gateway:192.168.1.1
# ipv4.dns:192.168.1.1,10.0.0.53,10.0.0.54

# 3. 应用配置（重启连接）
sudo nmcli connection up netplan-eno1
```

> 如果是 SSH 远程操作且新 IP 不同，第 3 步会断开当前 SSH 连接，
> 需要用新 IP 重新连接。**本例 IP 没变（从 DHCP 固定为同一个 IP），不会断网。**

## 参数详解

| 参数 | 值 | 说明 |
|------|-----|------|
| `ipv4.method manual` | 静态分配 | 改为 `auto` 则恢复 DHCP |
| `ipv4.addresses` | `192.168.1.13/24` | IP + 子网掩码（24 = 255.255.255.0）|
| `ipv4.gateway` | `192.168.1.1` | 默认网关（路由器地址）|
| `ipv4.dns` | 3 个 DNS | 逗号分隔，第一个是路由器，后两个是内网 DNS |

### DNS 为什么配 3 个

- `192.168.1.1`：路由器，负责公网域名解析
- `10.0.0.53` / `10.0.0.54`：内网 DNS，用于解析办公内网域名（如 VPN 相关）
- 顺序即优先级，前面的解析失败才用后面的

## 验证方法

```bash
# 1. IP 是否已固定（无 dynamic 字样 = 静态）
ip -4 addr show eno1 | grep inet
# 静态：inet 192.168.1.13/24 ... scope global noprefixroute eno1
# DHCP：inet 192.168.1.13/24 ... scope global dynamic noprefixroute eno1

# 2. 路由协议（static = 已固定）
ip route | grep default
# default via 192.168.1.1 dev eno1 proto static metric 20100

# 3. DNS 解析
nslookup baidu.com

# 4. 网关连通
ping -c 2 192.168.1.1

# 5. 服务可达
curl -s -o /dev/null -w "%{http_code}\n" http://192.168.1.13:8088/
```

## 恢复到 DHCP（回滚）

如果静态 IP 配置有问题，恢复到 DHCP 自动获取：

```bash
sudo nmcli connection modify netplan-eno1 ipv4.method auto
sudo nmcli connection down netplan-eno1
sudo nmcli connection up netplan-eno1
```

或重启网络管理器（兜底）：

```bash
sudo systemctl restart NetworkManager
```

## 配置持久化位置

nmcli 修改后，配置自动写入以下位置，重启自动生效：

| 文件 | 说明 |
|------|------|
| `/etc/netplan/90-NM-<UUID>.yaml` | netplan 配置（NetworkManager 生成）|
| `/etc/NetworkManager/system-connections/netplan-eno1.nmconnection` | NM 连接配置 |

> 不要手动改这两个文件，改了要 `sudo netplan apply` 或重启 NM 才生效。
> 日常修改一律用 `nmcli`。

## 常见问题

**Q1：改成静态 IP 后，还能连其他网络（如出差接别的路由器）吗？**

固定工位的台式机不存在此问题；如需移动，
建议用**路由器 DHCP 绑定 MAC** 方案（不改本机配置），或在出发前改回 DHCP。

**Q2：为什么不用 netplan 直接改 yaml？**

因为本机网络由 NetworkManager 管理（`renderer: NetworkManager`），
直接改 yaml 会被 NM 覆盖。nmcli 是 NM 的官方接口，改完自动同步。

**Q3：重启后 IP 会不会变？**

不会。静态配置已持久化到 netplan 文件，开机自动应用 `192.168.1.13`。
