# 32 · 工具 · 飞书（Feishu）

> 一句话：在 Ubuntu 上安装飞书官方 Linux 桌面版（deb 包），用于 IM 沟通 / 文档 / 多维表格 / 视频会议 / 登录飞书系产品（如 Antigravity、Qoder 的飞书扫码）。

---

## 背景

日常协作需要飞书桌面客户端（消息、文档、会议、扫码登录飞书系 IDE）。
飞书官方提供 Linux 原生客户端（Electron 实现），Ubuntu 24.04 用 `.deb` 包安装。

官网下载页（https://www.feishu.cn/download）是 React 动态页，`curl` 抓源码拿不到任何安装包链接，
链接由点击时调接口动态签发——但这个接口本身**稳定公开**，因此本方案比腾讯会议（docs/27）更优：
升级不用重抓直链，脚本零改动。

## 解决方案

### 一键执行（推荐）

```bash
cd <本仓库目录>
sudo bash scripts/install-feishu.sh
```

脚本会：

1. 调官网包信息接口取**当前最新版**的签名直链（直链短时效，即取即用）
2. 下载 `Feishu-linux_x64-<版本>.deb`（约 340M）到 `~/Downloads`，按接口给的 hash 做 **md5 完整性校验**
3. `dpkg -i` 安装，依赖缺失时自动 `apt -f` 修复（2026-09-22 实测缺 `pulseaudio-utils`，自动补装成功）
4. 校验 `dpkg -l` / `/usr/bin` 命令 / 桌面菜单项

### 核心机制：包信息接口（本方案的钥匙）

点击下载页的 Linux 下载按钮时，页面请求：

```
GET https://www.feishu.cn/api/package_info?platform=<N>
```

返回 JSON（2026-09-22 实测）：

```json
{
  "code": 0,
  "data": {
    "download_link": "https://lf9-ug-sign.feishucdn.com/ee-appcenter/fc38d53a/Feishu-linux_x64-7.72.23.deb?lk3s=...&x-expires=1790043510&x-signature=...",
    "version_number": "Linux-x64-deb@V7.72.23",
    "hash": "e7303dfa07c4b6a5e6ef7f92756bee94",
    "release_time": "1786694660"
  }
}
```

三个要点：

- **直链带签名短时效**（`x-expires` 几小时后失效），不能固化到脚本/文档里复用——必须每次现调接口
- **`hash` 字段就是 deb 的 md5**（实测与 `md5sum` 吻合），下载后可做完整性校验
- 接口不需要登录/Referer 之外的任何凭证，`curl` 直接可调

platform 取值全景（2026-09-22 实测探测）：

| platform | 包 | 说明 |
|----------|-----|------|
| **10** | Linux-x64-deb | **本机用这个** |
| 11 | Linux-x64-rpm | Fedora/RHEL/openSUSE |
| 12 / 13 | Linux-arm64-deb / rpm | ARM 机器 |
| 14 / 15 | Linux-mips64el-deb / rpm | 龙芯（版本线明显落后，7.22.9） |
| 9 | macOS-Apple | — |
| 1 | iOS | — |

### 手工步骤（理解原理用）

```bash
# 1. 取签名直链（python3 解析，直链含 & 不能 grep/sed 切）
URL=$(curl -s 'https://www.feishu.cn/api/package_info?platform=10' -H 'User-Agent: Mozilla/5.0' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["download_link"])')

# 2. 下载
curl -fL -A 'Mozilla/5.0' -o ~/Downloads/Feishu-linux_x64-7.72.23.deb "$URL"

# 3. md5 校验（与接口 hash 字段比对）
md5sum ~/Downloads/Feishu-linux_x64-7.72.23.deb

# 4. 安装（缺依赖时 apt -f 补）
sudo dpkg -i ~/Downloads/Feishu-linux_x64-7.72.23.deb
sudo apt-get install -f -y

# 5. 启动：Super 键搜 "飞书"，或命令行：
bytedance-feishu &
```


## 常见问题

**Q1：升级新版本怎么办？**

直接重跑 `sudo bash scripts/install-feishu.sh`——接口永远返回最新版直链，与 docs/27 腾讯会议的"版本耦合 hash 必须重抓"不同，本脚本升级零改动。（旧 deb 文件名不同会重新下载；装完旧版本被同名包覆盖升级。）

**Q2：为什么脚本里 python 输出用 `|` 分隔而不是 `KEY=VALUE` 让 eval？**

实测踩坑（2026-09-22）：直链含 `&`（`&x-expires=...`），裸 `eval` 会把 `&` 解释为 shell 后台符号；而给值加引号又需要 python 代码里写单引号——python 代码本身已被 shell 单引号包裹，内嵌单引号会截断字符串。管道分隔 + shell 参数展开切分是唯一干净的组合。

**Q3：怎么彻底卸载？**

```bash
sudo bash scripts/install-feishu.sh remove     # 系统包 + deb 安装包
rm -rf ~/.config/LarkShell                     # 用户数据（登录态/聊天缓存）
```

**Q4：下载页上 Linux 标着 "Beta"，稳定吗？**

Linux 版官方定位为 Beta（下载卡片右上角标签），但字节内部 Linux 用户量大，更新节奏快（7.x 主版本线），实测安装/启动正常。企业关键用途请自行评估。

**Q5：`bytedance-feishu` 和 `bytedance-feishu-stable` 两个命令有什么区别？**

同一个东西。deb 安装时通过 update-alternatives 把 `/usr/bin/bytedance-feishu`（别名）指向 `/usr/bin/bytedance-feishu-stable`（实际 wrapper 脚本）。两个都能启动。

**Q6：X11 / Wayland？**

本机为 X11 会话，2026-09-22 实测启动正常。若 Wayland 下遇屏幕共享黑屏，优先怀疑 Wayland 沙箱限制（同 docs/27 Q5）。

## 影响范围 / 安全权衡

- 安装目录 `/opt/bytedance/feishu/`（Electron 全家桶，约 1G 解压后）
- deb 自带 `bytedance-feishu.desktop`，应用列表直接可见
- 依赖 `pulseaudio-utils`（通知提示音），deb 未声明导致 dpkg 报错，`apt -f` 自动补
- 客户端联网飞书服务器（登录、消息、更新检查）
- 卸载不残留系统配置（用户数据在 `~/.config/LarkShell`）
