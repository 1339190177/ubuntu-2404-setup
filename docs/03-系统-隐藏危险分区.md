# 03 · 系统 · 隐藏危险分区（防止误操作）

> 让 Windows 系统盘等敏感分区不出现在文件管理器侧边栏、不自动挂载，从源头杜绝误操作损坏系统。

---

## 背景：为什么要隐藏？

双系统环境下，udisks2 会把检测到的分区自动挂到 `/media/<用户>/` 下，并显示在文件管理器侧边栏。这带来风险：

- **Windows 系统盘（C:）**：误删 `Windows/`、`Program Files/` 会让 Windows 启动不了
- **厂商恢复分区**：误操作可能破坏一键恢复功能
- **EFI 引导分区**：误删文件会让系统无法引导

双系统下最危险的通常是 **Windows 系统盘**，挂载参数甚至是 `rw`（可读写），一旦手滑后果严重。

## 目标分区（本机实测）

| 设备 | UUID | 类型 | 标签 | 处理 |
|------|------|------|------|------|
| `/dev/nvme0n1p4` | `<系统盘UUID>` | ntfs | Windows 系统盘 | ✅ 隐藏 |
| `/dev/nvme1n1p2` | `<EFI分区UUID>` | vfat | (无) | ✅ 隐藏 |
| `/dev/nvme0n1p5` | `<D盘UUID>` | ntfs | 数据盘 D | ❌ 保留（已挂载到 `~/win_d`）|
| `/dev/nvme0n1p6` | `<E盘UUID>` | ntfs | 数据盘 E | ❌ 保留（已挂载到 `~/win_e`）|

## 解决方案

### 一键执行（推荐）

直接复制下面命令到终端：

```bash
# 1. 卸载当前已挂载的目标分区
sudo umount -l "/media/$USER/<系统盘卷标>" 2>/dev/null
sudo umount -l "/media/$USER/<EFI分区UUID>" 2>/dev/null

# 2. 创建 udisks2 规则目录
sudo mkdir -p /etc/udisks2

# 3. 写隐藏规则（按 UUID 命名文件）
sudo tee /etc/udisks2/<系统盘UUID>.mount >/dev/null <<'EOF'
[Mount]
Hidden=true
EOF

sudo tee /etc/udisks2/<EFI分区UUID>.mount >/dev/null <<'EOF'
[Mount]
Hidden=true
EOF

# 4. 重启 udisks2 让规则生效
sudo systemctl restart udisks2
```

执行完后，这两个分区在文件管理器侧边栏不再出现，也不会被自动挂载。

### 原理说明

- udisks2 启动时读取 `/etc/udisks2/*.mount` 文件
- 文件名按"分区 UUID"匹配（注意 vfat/FAT 的 UUID 是 `XXXX-XXXX` 格式，文件名就是这个）
- `[Mount] Hidden=true` 告诉 udisks2：这个分区不要自动挂载、不在界面显示
- 重启 udisks2 服务立即生效，无需重启系统

## 验证方法

```bash
# 1. 确认规则文件存在
ls -l /etc/udisks2/*.mount

# 2. 确认目标分区未挂载
mount | grep -E "nvme0n1p4|nvme1n1p2"   # 应该没输出

# 3. 打开文件管理器，侧边栏应不再显示这两个分区
```

打开**文件管理器**，侧边栏应只剩：
- 你主文件夹的书签（文档、下载、win_d、win_e 等）
- 不再有 Windows 系统盘、<EFI分区UUID>

## 撤销方法（万一以后想恢复显示）

```bash
# 删掉对应的规则文件即可
sudo rm /etc/udisks2/<系统盘UUID>.mount   # 恢复 Windows 系统盘显示
sudo rm /etc/udisks2/<EFI分区UUID>.mount          # 恢复小分区显示
sudo systemctl restart udisks2
```

删除规则文件后，下次打开文件管理器，分区会重新出现在侧边栏。

## 万一真需要访问 Windows 系统盘怎么办？

隐藏只是"不让它自动挂"，**没禁止挂载**。真需要时（比如抢救 Windows 文件），手动挂：

```bash
# 临时挂载（用 sudo + 明确挂载点）
sudo mkdir -p /mnt/winsys
sudo mount -t ntfs-3g -o ro /dev/nvme0n1p4 /mnt/winsys
# 注意：用 ro（只读）挂载，最大限度保护数据
# 用完卸载
sudo umount /mnt/winsys
```

> 强烈建议：抢救 Windows 文件时用 `ro`（只读）挂载，看完就卸载，避免误写。

## 常见问题

### Q1：规则文件不生效，分区还是显示

**排查**：
```bash
# 文件名是否和 UUID 完全一致（区分大小写）
ls /etc/udisks2/
blkid | grep -E "nvme0n1p4|nvme1n1p2"

# udisks2 是否重启了
sudo systemctl status udisks2
```
注意 NTFS 的 UUID 是 16 位十六进制（`<系统盘UUID>`），FAT 的是 `XXXX-XXXX` 格式。

### Q2：隐藏后还能在"磁盘"应用（GNOME Disks）里看到吗？

**能**。`Hidden=true` 只影响 udisks2 的自动挂载和文件管理器显示，不影响底层分区表。在「磁盘」应用里仍能看到所有分区，需要时可以手动操作。

### Q3：重装 Windows 后 UUID 变了怎么办？

新 UUID 后旧规则文件失效（文件名对不上）。重新执行本文档命令，用新 UUID 建规则即可。旧的规则文件留着无害，也可一并删除。

## 影响范围

- ✅ **对数据零影响**：隐藏只是不显示，分区和数据毫发无损
- ✅ **可随时撤销**：删规则文件即可
- ✅ **保留底层访问能力**：「磁盘」应用、`sudo mount` 仍可手动访问
- ⚠️ **仅影响 udisks2 行为**：不影响已在 fstab 里的 `~/win_d`、`~/win_e`
