# 99 · 文档编写规范

> 本项目文档的命名、结构、风格约定。新增文档前请先读本文。

---

## 文件命名

### docs/ 目录

格式：`序号-主题-标题.md`

- **序号**：两位数字，`01` `02` `03` ...，决定文档在索引中的顺序
- **主题**：大类，例如 `双系统`、`系统`、`开发`、`网络`、`桌面`
- **标题**：中文，简明描述内容

示例：
```
01-双系统-Windows分区挂载.md
02-系统-sudo免密配置.md
03-系统-换国内源.md
04-开发-VSCode配置.md
99-文档编写规范.md      ← 本文件，规范类放 99 段
```

> **序号分配**：新增文档时取当前最大序号 +1。规范/元文档（如本文件）放 `99` 段。

### scripts/ 目录

格式：英文小写，单词间用短横线 `-` 分隔，加 `.sh` 后缀。

示例：
```
mount-windows.sh
setup-mirrors.sh
install-nvidia-driver.sh
```

## 文档结构（推荐章节）

每篇文档按需包含以下章节，未涉及的章节可省略：

```markdown
# 序号 · 主题 · 标题

> 一句话说明这篇文档解决什么问题。

---

## 背景
为什么要做这件事？痛点是什么？

## 目标 / 现状
（如涉及硬件/分区）列出关键信息（UUID、IP 等对外发布请占位化，见 AGENTS.md 安全纪律）。

## 解决方案
### 一键执行（推荐）
### 手工步骤（理解原理用）

## 参数 / 配置详解
解释每个关键参数为什么这么设。

## 验证方法
如何确认配置生效。

## 脚本用法
（如有配套脚本）

## 常见问题
Q1 ... Q2 ...

## 影响范围 / 安全权衡
（如有安全考量）

## 变更记录（维护者私有惯例，公共贡献可省）
| 日期 | 改动 |
```

## 写作风格

### 语言
- **全中文**，目标读者是未来的自己
- 命令、变量名、配置项、专有名词保留英文原词（如 `fstab`、`UUID`、`ntfs-3g`）

### 语气
- 直接、简洁、可执行
- 少用"建议"、"也许"，多用"执行 X"、"检查 Y"
- 每个操作步骤都要能直接复制粘贴执行

### 排版
- 用表格对比参数、选项、方案
- 用代码块包住所有命令和配置
- 命令前加 `#` 注释说明做什么
- 长输出截取关键行，用 `...` 表示省略

### 示例对比

❌ 不好：
```
你可以试试改一下 fstab，加上 uid 参数应该就行了。
```

✅ 好：
```bash
# 编辑 fstab，把 uid=1000 加到挂载选项里
sudo nano /etc/fstab
# 修改对应行：
# UUID=... ~/win_d ntfs-3g uid=1000,... 0 0
```

## 关键原则

1. **真实可复现**：所有命令、UUID、参数必须来自本机实测，不写占位符（除非确实是变量）。
2. **解释为什么**：不只给命令，要说明每个参数的作用和取舍。
3. **可撤销**：每项配置都给出撤销/还原方法。
4. **变更留痕**：每次修改文档更新「变更记录」表。

## 配套脚本规范

`scripts/` 下的脚本应：

1. **shebang**：`#!/bin/bash`
2. **set 选项**：至少 `set -u`；自动化脚本可用 `set -euo pipefail`
3. **颜色输出**：参考现有 `mount-windows.sh` 的 `info/ok/warn/err` 函数
4. **帮助信息**：`--help` 参数或无参数时显示用法
5. **交互菜单 + 命令行参数双模式**：参考 `mount-windows.sh` 的 `main "$@"` 设计
6. **错误处理**：关键操作失败要中止并给出可操作的提示
7. **可执行权限**：`chmod +x`

## 更新索引

新增/删除文档后，**必须**同步更新 [`README.md`](../README.md) 的「文档索引」表。

## 提交规范（git）

```bash
git commit -m "<type>: <描述>"
```

type 取值：
- `feat`：新增功能/配置
- `fix`：修复问题
- `docs`：仅文档变更
- `refactor`：重构（不改行为）
- `chore`：杂项（.gitignore、目录调整等）

示例：
```
feat: 新增 Windows 数据盘挂载配置
fix: 修正 win_d 的 UUID
docs: 补充常见问题章节
```
